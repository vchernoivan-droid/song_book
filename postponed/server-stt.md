# STT-сервер (self-hosted Whisper на маке)

Статус: обсуждение, решения согласованы, код не начат.

## Место в общей схеме

Основной путь STT (см. `on-device-stt.md`): микрофон → наш сервер → лучший
Whisper → partial-гипотезы обратно в приложение. Офлайн on-device —
fallback, отдельная ветка.

## Согласованные решения

- **Машина:** MacBook Pro, Apple M4 Pro (12 ядер, 24 ГБ) — он же лэптоп в
  локальной сети.
- **Движок:** whisper.cpp + Metal. `faster-whisper` не подходит: GPU только
  через CUDA, Metal не поддерживает.
- **Модель:** конфигурация (путь к GGML-файлу). Отправная — `large-v3-turbo`
  (баланс скорость/качество), при необходимости — `large-v3`. Все модели
  один формат/один API, меняются на лету перезагрузкой весов; выбор модели
  сейчас не фиксируем, пробуем на живом пении.
- **Обвязка:** Python — `pywhispercpp` (whisper.cpp) + FastAPI/aiohttp
  WebSocket + silero-vad. Выбрано как самый быстрый прототип; для продакшена
  можно позже переехать на Go/C++.
- **Режим:** потоковый real-time. whisper.cpp сам не стриминговый → обвязка:
  VAD находит речь → копит буфер → перезапускает инференс на растущем буфере
  → отдаёт накопленный текст как partial каждые ~0.5–1 с.
- **Сеть:** локальная. Сырой PCM 16 кГц mono int16, без кодеков.
- **Протокол WebSocket:**
  - клиент → сервер: binary PCM чанками ~20–50 мс; JSON `{type:"start"}`,
    `{type:"stop"}`;
  - сервер → клиент: JSON `{type:"partial", text, confidence}`,
    `{type:"final", text, confidence}`, `{type:"error", message}`.
- **Поиск сервера:** по QR-коду, как в remote-mic (лэптоп в локальной сети).

## Клиентская сторона

Новая реализация `HeardFeed` (`ServerSttFeed`): захват микрофона в PCM
(плагин `record` — сейчас `speech_to_text` держит микрофон сам), WebSocket,
PCM вверх, `partial`/`final` вниз → `HeardEvent` → `LyricLocator`.
Уровень громкости для индикатора считаем на клиенте из того же PCM.
Текст песни серверу не нужен — локатор остаётся на клиенте.
В UI — переключатель источника: системный STT / сервер / (позже on-device).
