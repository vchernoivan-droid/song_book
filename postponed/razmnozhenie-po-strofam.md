# Размножение аккордов по строфам + закалка границ секций

Статус: план согласован, отложено. Завязано на баг-репорт «Любовь и разлука»: при «Размножить аккорды» аккорды первого куплета заезжали в куплеты и припевы. Исходник утрачен (песня пересобрана), точный триггер не восстановлен, но уязвимость механизма воспроизведена (см. ниже). Подсветка заголовков/аккордов в редакторе и просмотре уже закоммичена (e4a5ce3) — она визуализирует, что парсер распознал.

## Диагноз (сессия 17–18 окт)

`propagateChords` (`song_parser_propagate.dart`) мапит строки шаблона на строки цели плоским индексом по всей секции, игнорируя `Line.stanzaStart`. Любая асимметрия числа строк внутри секции (повтор строк только в шаблоне, лишняя/пропавшая строка, аккордная строка без текста) сдвигает индексы — аккорды переезжают через границу строфы на чужой текст (хвост куплета — на первые строки припева).

Уязвимости разметки, которые превращают секцию в смесь «куплет+припев» (все подтверждены репродьюсами):

1. Блок без заголовка приклеивается к предыдущей секции — куплет без метки после `[Припев]` живёт внутри chorus-секции.
2. Нет пустой строки перед заголовком — `[Припев]` не в начале блока становится обычной строкой текста, граница секции теряется навсегда (внешне текст выглядит нормально, поэтому незаметно; похоже на реальный триггер бага).
3. Аккорды на строке заголовка (`[Припев] F C`) — вообще не заголовок.
4. `Слово:` без ключевого слова типа («Вставка:», «Модуция:») — не заголовок, тихое слияние.
5. Любой `[...]` в начале блока — всегда заголовок: `[Am]` режет песню неизвестной секцией (а `[Am]` в середине блока — аккордная строка, асимметрия).

`[Куплет]` без номера уязвимостью не является — распознаётся нормально, номер косметика.

## План правок

### 1. Строфо-осознанное размножение (`song_parser_propagate.dart`)

`_applyTemplate`: резать `template.lines` и `target.lines` на строфы по `stanzaStart`; мапить строфа→строфа, внутри пары строка→строка по индексу:

- целевая строфа длиннее пары шаблона → продолжаем следующей строфой шаблона (сохраняет тест «многострофный куплет — одна секция, размножение по строкам»);
- целевая строфа кончилась, у шаблона остались строки → остаток выбрасываем, через границу целевой строфы он не переезжает. Это убирает заезд аккордов через границу строфы.

Проверено на сценариях: `[К1(стих), П1(6 строк с повтором)] → [К2(стих короче), П2(4 строки)]` — хвост куплета не касается припева, припев берёт аккорды из строфы припева шаблона.

### 2. Закалка парсера: заголовок в середине блока (`song_parser_parse.dart`)

Резать блок на секции, если заголовок (`isSectionHeaderText`) встретился в середине блока. Порядок проверок важен: сначала `isChordLineText` — аккордная строка остаётся аккордной (`[Am]` над текстом и `[Припев]:Dm A7` не становятся заголовками), иначе заголовок.

### 3. Тесты и доки

- кейс «Любовь и разлука»: припев без метки куплета поблизости + повтор строк только в шаблоне → аккорды не пересекают границу строфы;
- идемпотентность кейса через parse→render→parse;
- заголовок в середине блока режет секцию;
- прогон всей группы `propagateChords` + обновить `docs/song-model.md` (раздел «Размножение аккордов» описывает плоский маппинг).

## Открытые вопросы

- «Вставка:», «Модуция:» — расширять словарь ключевых слов или оставить слияние (риск ложных заголовков на репликах «Скажи:»)?
- `[Am]` в начале блока — заголовок или аккорд? Сейчас асимметрично: начало блока → секция, середина → аккордная строка.
- Пустые секции (`[Припев]` без строк) — связка с `povtor-pripeva-bez-teksta.md`.
