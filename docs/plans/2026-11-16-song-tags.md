# Тэги-плейлисты: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Локальные тэги-плейлисты: тэг на песне, фильтр по тэгу на главном экране, диалог управления тэгами.

**Architecture:** Тэги — атрибут песни: карта `имя_файла → [имена_тэгов]` в одном JSON-ключе `shared_preferences` (паттерн `PrefsSongStorage`). Отдельной сущности «плейлист» нет: список всех тэгов = объединение по песням, пустых тэгов не бывает. UI: чипы на строках главного экрана + фильтр, диалог управления из экрана песни.

**Tech Stack:** Flutter/Dart, `shared_preferences`, `flutter_test` (`SharedPreferences.setMockInitialValues`).

**Spec:** дизайн согласован в обсуждении (тэг = группировка; без порядка; создание в диалоге; переименование/удаление тэга длинным тапом/правым кликом; имена тэгов отдельно от текстов песен).

## Global Constraints

- Пакет `song_book`, рабочая папка команд — `mobile-app/`.
- Без комментариев в коде: ни `///`, ни `//` (правило AGENTS.md).
- UI-строки на русском.
- Тэг — непустая строка после `trim`; регистр значим («дом» ≠ «Дом»); дубликаты точного совпадения игнорируются.
- Формат хранения: ключ prefs `tags_data`, JSON `Map<String, List<String>>`; списки хранятся отсортированными (по lower, затем по raw).
- Коммитим только файлы своей задачи; `postponed/razmnozhenie-po-strofam.md` (удалён, ждёт своего коммита) в коммиты задач не включать.

## Review Focus

1. Переименование песни в редакторе не должно терять её тэги — тест в Task 5.
2. Удаление песни свайпом не должно оставлять висящую запись в карте тэгов — тест в Task 4.
3. Переименование тэга должно обновить все песни, не только открытую в диалоге — тесты в Task 1 и Task 2.
4. Пустое/пробельное имя нового тэга не должно создаваться — тест в Task 2.
5. Имя файла без записи в карте (новая песня) читается как `[]` без падений — тест в Task 1.

### Task 1: TagStore

**Files:**
- Create: `mobile-app/lib/services/tag_store.dart`
- Test: `mobile-app/test/tag_store_test.dart`

**Interfaces:**
- Consumes: `shared_preferences` (уже в зависимостях).
- Produces: `class TagStore` с методами (все асинхронные):
  - `Future<Map<String, List<String>>> all()`
  - `Future<Set<String>> allTags()` — объединение значений, отсортировано
  - `Future<List<String>> tagsOf(String fileName)` — `[]` при отсутствии записи
  - `Future<void> setTags(String fileName, List<String> tags)` — trim, пустые убрать, дубликаты схлопнуть, отсортировать; пустой результат → удалить запись
  - `Future<void> renameTag(String oldName, String newName)` — замена во всех записях (коллизии мержатся)
  - `Future<void> deleteTag(String name)` — убрать из всех записей, опустевшие записи удалить
  - `Future<void> renameSong(String oldFileName, String newFileName)` — перенос записи (no-op при равенстве или отсутствии старой; при занятой цели — мерж)
  - `Future<void> deleteSong(String fileName)` — удалить запись

- [ ] **Step 1: Написать падающие тесты**

Имена тестов: `пустое хранилище — all пустая и allTags пусто`, `setTags нормализует: trim, дубликаты, сортировка`, `setTags пустым списком удаляет запись`, `tagsOf отсутствующего файла — пустой список`, `renameTag обновляет все песни`, `deleteTag чистит все записи и удаляет опустевшие`, `renameSong переносит тэги, no-op при том же имени`, `renameSong мержит при занятой цели`, `deleteSong удаляет запись`, `allTags — объединение и сортировка по lower`.

Setup каждого теста: `SharedPreferences.setMockInitialValues({})` (или предзаполненный `tags_data`), затем `TagStore()`.
