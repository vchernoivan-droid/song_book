# LyricLocator — матчинг пения со строками песни

Код: `mobile-app/lib/services/lyric_locator.dart`.
Тесты: `mobile-app/test/lyric_locator_test.dart`.
Реплей: `cd mobile-app && dart run tool/replay_locator.dart <song.txt> <log>`.

## Задача

Превращает поток partial-гипотез STT (пение, conf 0.2–0.3, текст искажён)
в индекс логической строки песни, которую поют сейчас. Индекс совпадает
с `_layout.tops`/`_pos` на экране песни → результат напрямую ложится в
`singerLine` (стрелка певца) и курсор автоскролла.

## Свойства входа

- Каждый partial — полный накопленный текст с начала сессии; final
  приходит только в конце сессии и для follow бесполезен.
- partial переписывает историю (≈половина апдейтов меняет уже выданные
  слова) → partial'ы не диффятся, слова не копятся инкрементально.
- Частота ~2–3/с, рост ~1 слово за апдейт.

## Конвейер

Текст песни: нормализация → индекс → склеенная лента символов `_chars`
+ `_charLines` (символ → строка).

Поток STT: нормализация → хвост последних 8 слов → DP-Левенштейн по
ленте → `sim` по позициям → якорь → порог → стрелка/курсор.

## Нормализация (фонетический ключ v1)

`phoneticKey` прогоняет слово через правила «как звучит» (обе стороны —
песня и распознавание):

- lowercase, `ё→е`, оставить только буквы/цифры;
- убрать `ь`/`ъ`;
- `о→а`, `е→и` — аканье/иканье (помета ударения нет, применяется
  безусловно);
- оглушение конечных звонких: `год→гот`, `дуб→дуп`;
- сжать удвоенные согласные.

Лечит самые частые замены ASR в русском. Не покрывает «синий/сидит»
(н↔д, й↔т) — это территория матрицы замен (дальнейший шаг, в `TODO`).

## Индекс песни (строится один раз при открытии)

Из `ParsedSong`, обход в порядке `renderSongLines` (тот же, что у
`tops`):

- каждая `Line` получает порядковый номер; прогрессии и табы
  (`isProgression`) номер занимают, слов не дают — матчиться не по чему;
- слова восстанавливаются из `SyllableToken`: `dash == none|right` —
  начало слова, `both|left` — продолжение; дефисные «кто-то» склеиваются;
- результат — склеенная лента `_chars` из нормализованных слов и
  параллельный `_charLines` (номер строки каждого символа).

## Хвост

`tail = последние min(8, len) слов` полного накопленного текста (после
`keysOf`). 8 слов ≈ 3 с пения ≈ 2–3 строки контекста, по которому шум
усредняется. Одно слово шумит, точная подстрока мертва при conf 0.2.

## DP-Левенштейн (полуглобальный)

Хвост склеивается в строку `t` и выравнивается по всей ленте `_chars`
(`n = |t|`, `m = |_chars|`):

- `dp[i][j]` — цена выравнивания `t[0..i)` на `_chars[0..j)`;
- `dp[i][0] = i·gapCost` (хвост глобальный — весь должен выровняться),
  `dp[0][j] = 0` (начало в ленте свободное — песня может стартовать в
  любом месте);
- замена `substitutionCost 1.15`, вставка/удаление `gapCost 1.0`;
- замена дороже удаления — лишние/пропавшие слоги распознавания
  штрафуются мягче, чем замена «чужого» звука.

Для каждой позиции `j` ленты:

    sim(j) = 1 − dp[n][j] / n

## Позиция — по последнему слову хвоста

Обратным ходом из лучшего `j` восстанавливается выравнивание, затем по
словам хвоста с конца ищется слово, у которого:

- длина ≥ `minExtendingWordLength 2`;
- доля точно совпавших символов ≥ `wordExactShare 0.8`.

Его строка (`_charLines[wordEnd]`) — строка, которую поют сейчас.
Так вставки/пропуски целых слов в хвосте не сдвигают позицию: решает
последнее уверенно выровненное слово.

## Якорь (повторяющиеся припевы)

Идентичные припевы дают одинаковый `sim` на всех вхождениях — argmax
всегда брал бы первое. Эффективная оценка штрафует удаление от последней
найденной строки:

    eff(j) = sim(j) − штраф

- назад (`d < 0`): `min(backPenalty·(−d), maxBackPenalty)`;
- вперёд дальше `forwardFree 2` строк:
  `min(forwardPenalty·(d−forwardFree), maxForwardPenalty)`;
- первые 2 строки вперёд — бесплатно (нет дрожания на соседних строках).

`best = argmax eff`; при равном `sim` побеждает ближайшее вхождение.
Пересилить якорь с дистанции 10 строк можно только выигрышем 0.2 по
`sim` — при искажённом распознавании не бывает.

## Порог

`sim < minScore 0.4` — кандидат отбрасывается; если никого не осталось →
`null` («не понял»). `null` = держим позицию (пауза, проигрыш,
нераспознавшийся кусок), не ошибка.

## Сглаживание на экране (`song_detail_screen.dart`)

`_onRecognized` → `locate(keysOf(words), previousLine: _matchedLine)`:

- `null` → держим стрелку;
- `line == current` → ничего;
- иначе → `_matchedLine = line`, `singerLine.value = line`, плавное
  преследование скролла (`_pursuitTau 3.0`).

Сброс позиции: 15 с тишины (`_onSilenceTimeout`), тап по гуттеру,
колесо/драг — ставят стрелку на ближайшую строку. Вперёд скачки
разрешены (плохо спетый кусок пропускается, курсор догоняет); назад без
сброса не ходим.

## Параметры

| Параметр | Значение | Смысл |
|---|---|---|
| `tailWords` | 8 | ~3 с пения, 2–3 строки контекста |
| `substitutionCost` | 1.15 | замена дороже удаления |
| `gapCost` | 1.0 | вставка/удаление |
| `backPenalty` | 0.03/строка | различает повторы |
| `forwardPenalty` | 0.02/строка | не душит скачки вперёд |
| `forwardFree` | 2 | первые строки вперёд бесплатно |
| `maxBackPenalty` | 0.30 | потолок штрафа назад |
| `maxForwardPenalty` | 0.20 | потолок штрафа вперёд |
| `minScore` | 0.4 | ниже — мусор/тишина, держим позицию |
| `wordExactShare` | 0.8 | доля точных символов в последнем слове |
| `minExtendingWordLength` | 2 | короче — не позиционируемся |

## Валидация

Две живые сессии:

- пение 22:25 — 95% матчей, |Δ| p50 1.5, max 3.2; бубнение на стыке
  куплетов стрелку не двигает;
- речь 21:29 — 96% матчей, |Δ| p50 1.7.

Попарное окно (предыдущая версия) давало p50 2.0, max 8.0.

позиция автоскролла в момент события (две кривые в одном логе: курсор и

<song.txt> <log>`.
